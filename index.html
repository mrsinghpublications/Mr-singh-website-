Firebase Auth Setup (No-Code)

Paste your Firebase web-app config JSON here. Until then the store runs in Demo Mode (OTP is shown in a gold toast, Google login is simulated). With keys saved, Google sign-in and Phone OTP use live Firebase Auth.

Mode: Demo (no keys saved)
Step-by-step Firebase setup guide
  1. Go to console.firebase.google.com → Create project → Build → Authentication → Get started.
  2. Sign-in method: enable Google and Phone.
  3. Project Settings → Your apps → Web app (</>) → copy the firebaseConfig object.
  4. Paste the whole JSON above and press Save Payment Settings.
  5. For Phone OTP: in Authentication → Settings → Authorized domains, add your GitHub Pages domain (e.g. username.github.io).
  6. Reload the store — the Auth modal will say “Live Firebase Mode” and real OTPs will be sent.

Firebase — Auth, Firestore & Storage (optional, no-code)

One Firebase config (above) powers all three. Auth: customers + admin login with Google / Phone OTP. Firestore: books list + order history saved in the cloud, so they survive clearing browser data. Storage: cover photos + eBook PDFs uploaded to the cloud instead of browser storage.

Not tested yet
Website vs App security: Website shows both Customer Login and Admin Panel. The App is customer-only — when the app User-Agent (MrSinghApp) or ?app=1 / installed PWA is detected, the Admin button is hidden and #/admin returns a 403 screen in this file. This alone is not real security — add the matching server rule at your host (README.md has the ready-made rule for .htaccess / Cloudflare / Firebase Hosting) so the block holds even if someone edits the page in their browser.
Firestore & Storage setup guide
  1. Firebase Console → Build → Firestore Database → Create database (production mode) → Collections used: books, orders, ebookRequests, customers.
  2. Firestore Rules (start with test rules, then lock down): allow read for all, write only for signed-in users — paste your rules in Console → Firestore → Rules.
  3. Build → Storage → Get started → folders used: covers/ and ebooks/. Set Storage rules to allow authenticated uploads.
  4. Cloudflare R2: R2 cannot be uploaded to safely from a browser with secret keys, so R2 mode works as “paste public link”: upload the file in the Cloudflare dashboard (R2 → your bucket → Upload), make it public (Settings → Public access / custom domain), then paste its public URL in the book form. Put the bucket base URL above so the app can check it.
  5. Save settings, reload the store, and press Test — the status line shows which of Auth / Firestore / Storage is live.

eBook Email Delivery — EmailJS (optional, for automatic email)

Without this, the buyer still gets an instant download + password in the app, and an “Email me the eBook” button that opens their email app pre-filled. With EmailJS filled in, the eBook link + password is emailed automatically on order confirmation. Free plan at emailjs.com: create a Service (Gmail) + Template with variables to_email, book_title, ebook_link, ebook_password, order_id.
